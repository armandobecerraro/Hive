impl Worker {
    async fn execute_real_task(&self, task: &Task) -> Result<TaskResult> {
        // 1. Generar código real
        let changes = self.brain.generate_real_code(task, &context).await?;
        
        // 2. Aplicar cambios al filesystem
        for change in &changes {
            self.apply_file_change(change).await?;
        }
        
        // 3. Crear commit real
        self.git_commit(&changes, task).await?;
        
        Ok(TaskResult { changes, success: true, .. })
    }
    
    async fn apply_file_change(&self, change: &FileChange) -> Result<()> {
        let path = self.target_dir.join(&change.path);
        match change.action {
            FileAction::Create | FileAction::Modify => {
                std::fs::write(&path, &change.content)?;
            }
            FileAction::Delete => {
                std::fs::remove_file(&path)?;
            }
        }
        Ok(())
    }
}

// Agente escucha feedback
impl Worker {
    async fn listen_for_feedback(&self, feedback_rx: &mut FeedbackReceiver) {
        while let Some(feedback) = feedback_rx.recv().await {
            if feedback.worker_id == self.id {
                self.process_feedback(feedback).await;
            }
        }
    }
    
    async fn process_feedback(&self, feedback: WorkerFeedback) {
        match feedback.decision {
            Decision::Approved => {
                self.celebrate_and_die().await;
            }
            Decision::Rejected => {
                // Leer comentarios y ajustar código
                self.adjust_code_based_on_comments(&feedback.comments).await;
                // Reintentar
                self.retry_task().await;
            }
        }
    }
}

## Mejora 4: Autodestrucción y Liberación de Recursos (Semana 2)

### Lifecycle Manager en `orchestrator.rs`
```rust
struct WorkerLifecycleManager {
    workers: HashMap<Uuid, WorkerHandle>,
    resource_monitor: ResourceMonitor,
}

impl WorkerLifecycleManager {
    async fn monitor_and_cleanup(&mut self) {
        loop {
            tokio::time::sleep(Duration::from_secs(30)).await;
            
            // 1. Verificar workers sin tareas por >5min
            for (worker_id, handle) in &self.workers {
                if handle.idle_time() > Duration::from_secs(300) {
                    self.terminate_worker(*worker_id).await;
                }
            }
            
            // 2. Verificar workers completados exitosamente
            for (worker_id, handle) in &self.workers {
                if handle.status() == WorkerStatus::Completed {
                    self.terminate_worker(*worker_id).await;
                }
            }
            
            // 3. Verificar uso de RAM
            if self.resource_monitor.memory_usage() > 0.8 {
                self.terminate_lowest_priority_worker().await;
            }
        }
    }
    
    async fn terminate_worker(&mut self, worker_id: Uuid) {
        if let Some(handle) = self.workers.remove(&worker_id) {
            handle.terminate().await;
            tracing::info!(worker_id = %worker_id, "Worker terminated and resources freed");
        }
    }
}
```

## Mejora 5: Actualización de version.json (Semana 3)

### Version Manager
```rust
struct VersionManager {
    path: PathBuf,
}

impl VersionManager {
    pub fn new(repo_path: &Path) -> Self {
        Self {
            path: repo_path.join("version.json"),
        }
    }
    
    pub fn record_merge(&self, mr_id: &str, worker_id: Uuid, changes: &[FileChange]) -> Result<()> {
        let mut version_data = self.load()?;
        
        version_data.versions.push(VersionEntry {
            id: Uuid::new_v4(),
            timestamp: chrono::Utc::now(),
            mr_id: mr_id.to_string(),
            worker_id,
            changes_count: changes.len(),
            files_changed: changes.iter().map(|c| c.path.clone()).collect(),
        });
        
        version_data.current_version += 1;
        
        self.save(&version_data)
    }
}
```

## Riesgos y Mitigaciones

### Riesgo 1: LLM genera código no compilable
**Mitigación**:
- Parser estricto con validación de sintaxis
- Fallback a código template si LLM falla
- Tests de compilación después de generación

### Riesgo 2: Conflictos de merge no manejables
**Mitigación**:
- Agentes monitorean archivos en tiempo real
- Locking a nivel de archivo
- Escalación a Consejo para conflictos complejos

### Riesgo 3: Memory leaks en ejecución larga
**Mitigación**:
- Timeout automático de workers (5min)
- Garbage collection periódico
- Monitor de recursos con alertas

## Conclusión
Con este plan de 3 semanas, The Hive pasará de ser un "shell arquitectónico" a un sistema funcional que cumple con el 95%+ de los requisitos originales. La priorización en código real y MRs reales asegura que el sistema produzca valor tangible desde el primer sprint.
